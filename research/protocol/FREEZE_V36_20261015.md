## What v3.6 is
- `sweep_analysis_v3_6.py` imports the frozen v3.3 reader and, for one run, rebinds **three** names (a context manager restores them; tested):
  1. v3.3's `ADDED_PROFILES`: its `teastore-offpath-v1` entry replaced by `parameters_v3_6.json`'s `V36_EPOCH_PROFILES`, which differs from v3.3's entry in **exactly one key, `role`**
     (`offpath-teastore` -> `campaign-E`; import-time assertion). v3.2 selects campaign-E epochs by that key alone, so the epoch gets v3.2's block selection (V32_BLOCK_SELECT_RULE), the
     held-out rule, the split check against `V32_E_SPLIT` (1-3 / 4-5) and the one-new-epoch refusal, exactly as E and F.
  2. v3.2's `_read_block`: v3.2 reads (studyEpoch, block) from the receipt's `runKey`, which TeaStore receipts do not have (top-level `studyEpoch`, `run.block`). v3.6 returns v3.2's answer for
     any receipt with a `runKey`, and (studyEpoch, run.block) for a receipt without one whose studyEpoch is `teastore-offpath-v1`; everything else stays (None, None). Without it v3.2 refused
     `--blocks` on replication 2 ("no cell of a campaign-E epoch").
  3. v3.3's `_ORIG_CTX` (its handle on `v32_context`): for system teastore, v3.2's **decision-102 train-only hooks** are installed as v3.2 installs them for otel (`fits_for3_32`, `loco_fits3_32`,
     `loco_fits_reference_32`, `operating_point_32`, `pair_fits_32`, `calibrate32`, `validation32`, `make_ctx32`; v3.2's own functions, unchanged). v3.2 installs them only under
     `system == "otel"`; without them a TeaStore read with `--test-blocks 4 5` flagged the test cells heldOut and still calibrated on them (replication 2: 5 no-fault cells per rate in the
     scoring readout's calibration against 3 in the training readout; `score_test_v3_2` refused, decision 102). None of v3.2's OTel-only rebindings (ledger kind, OTel ledger/loader, path_of,
     pause regime, eval_episode3, exposure, P1/P2) is installed.
  No v3.3 function is replaced; no level rule, cost model, lane rule or placement logic changed. Any `--system` but `teastore` is refused.
- `celf_v3_6.py`: celf_v3_2's frontier over a v3.6 readout (v3.6, v3.3, v3.2 layers; pins `PINNED_V36_SHA256`, `PINNED_PARAMETERS_V36_SHA256` below). **Engineering default (V36_TIERS_RULE):**
  TeaStore has no tier file in celf_v3_2's schema and none is invented: `--tiers` is not taken, every candidate is `tiersMissingForGroundSet`, only the (effort<=any, runtime<=any) cell admits it.
- `score_test_v3_6.py`: score_test_v3_2 unchanged, with the v3.6 input checks and the pass rule **`V36_PASS_RULE`** from the v3.6 registry (not v3.2's, whose classes are OTel's):
  class `recommender-pause-effect`, at rate 10 and at rate 1 separately, set `frontier (effort<=any, runtime<=any) @6/T_r`, `minGain` null (strictly positive g), `minImprovedEpisodes` 2,
  `minEpisodes` 2; dash below 2 valid test episodes (decision 91) or with an absent member (decision 90). `auth-freeze-effect` carries no verdict. Decision 73 unchanged.
  `PINNED_PLACEMENTS` is **empty** (step 2 below). The output's `passRuleNote` is score_test_v3_2's inherited label ("decision 99 (V32_PASS_RULE …)"); `inputs.passRuleSource` says the rule is V36's.
